# 🏗️ MASTER PROMPT: Hearth — Household Management App

## 1. Описание проекта и Технический стек
**Название:** Hearth
**Суть:** Мобильное/десктопное приложение для совместного управления бытом двух пользователей (cohabitants).
**Стек технологий:** 
*   **Frontend:** Flutter (кроссплатформенная сборка).
*   **Backend/BaaS:** Firebase (Cloud Firestore для базы данных, Firebase Auth для авторизации).
*   **State Management:** Riverpod (или Provider).
*   **Routing:** GoRouter.

## 2. Дизайн-система (UI/UX)
Приложение должно выглядеть минималистично, современно и уютно.
*   **Типографика:** 
    *   Заголовки: `Libre Baskerville`.
    *   Основной текст: `Instrument Sans`.
    *   Цифры (бюджет, количество): `DM Mono`.
*   **Цветовая палитра:**
    *   Фон: Кремовый (`Cream`) с мягким градиентом.
    *   Кнопки действий (Primary): Мшисто-зеленый (`Moss-green`).
    *   Цвета пользователей: Пользователь 1 — Терракотовый (`Terracotta`), Пользователь 2 — Шалфей (`Sage`).
    *   Алерты: Янтарный (`Amber`) при приближении к лимиту, Красный (`Red`) при превышении.
*   **Стиль компонентов:** Карточки с легкими тенями, скругленные углы, визуальное разделение блоков без жестких границ.

## 3. Архитектура данных (Firebase Firestore Collections)
*   **`users`**: `{uid, name, color (terracotta/sage), household_id}`
*   **`households`**: `{id, members: [uid1, uid2], created_at}`
*   **`budget_transactions`**: `{id, amount, category, date, description, added_by}`
*   **`budget_categories`**: `{id, name, monthly_limit, current_spent}`
*   **`inventory`**: `{id, name, location (Pantry/Fridge/Freezer/Household), quantity, unit, low_stock_threshold, is_running_low}`
*   **`recipes`**: `{id, name, ingredients: [{item_name, required_quantity}], prep_time}`
*   **`meal_plan`**: `{id, date (Mon-Sun), recipe_id, is_cooked}`
*   **`tasks`**: `{id, name, assigned_to (uid), status (done/pending), date_assigned}`

## 4. Структура приложения (5 основных вкладок)

### Вкладка 1: Overview (Дашборд)
*   **Блок Бюджета:** Крупным шрифтом (DM Mono) остаток средств на месяц (например, $1,280) и прогресс-бар.
*   **Running Low (Инвентарь):** Список продуктов, которые заканчиваются.
*   **Today's Chores & Dinner:** Запланированный на сегодня ужин и список задач для обоих пользователей с чекбоксами.

### Вкладка 2: Budget (Бюджет)
*   **Total:** Месячный лимит и остаток.
*   **Categories:** Список категорий (Groceries, Rent, Utilities, etc.) с прогресс-барами. Логика цвета: зеленый -> янтарный (близко к лимиту) -> красный (превышение).
*   **Log an expense:** Форма добавления расхода (Сумма, Категория, Описание).
*   **Recent:** История последних транзакций.

### Вкладка 3: Inventory (Запасы)
*   **Категоризация:** Группировка списков по локациям (Pantry, Fridge, Freezer, Household, Laundry).
*   **Управление:** У каждого товара есть кнопки `+` и `-` для быстрого изменения количества.
*   **Shopping List:** Автоматически генерируемый список покупок на основе товаров, чье количество упало ниже критического минимума (low stock).
*   **Add Item:** Форма добавления нового продукта в базу.

### Вкладка 4: Meals (Питание)
*   **This week's dinners:** Горизонтальный план на 7 дней (Пн-Вс). Под каждым днем — кнопка «Mark cooked».
*   **Recipe Box:** Карточки рецептов. Подтягивают ингредиенты из базы. Система автоматически подсвечивает отсутствующие на складе ингредиенты красным.
*   **Киллер-фича (Логика списания):** При нажатии кнопки «Mark cooked» в планере, система должна найти все ингредиенты рецепта в `inventory` и вычесть их количество.

### Вкладка 5: Cleaning (Уборка)
*   **Интерфейс:** Сетка задач на неделю. Наверху — аватары/имена пользователей (Maya и Jonah) с их персональными цветами и общим прогресс-баром выполнения задач.
*   **Распределение:** Клик по имени пользователя на задаче передает эту задачу ему (меняется цвет тега).
*   **Smart Features:** Кнопка «Balance load» (автоматически распределяет задачи поровну между юзерами) и «Swap & new week» (очищает галочки и меняет пользователей местами на рутинных задачах).

## 5. Правила работы ИИ-ассистента (AI Guidelines)
1.  **Atomic Commits:** Не пиши все приложение в одном файле. Разделяй логику, UI и модели данных. Начинай генерацию с `models/`, затем `providers/`, затем `screens/`.
2.  **No Placeholders:** Пиши полностью рабочий код. Если нужна функция вычитания ингредиентов из Firebase — пиши реальный запрос к Firestore, а не `// TODO: implement logic`.
3.  **UI Fidelity:** Строго соблюдай типографику и цвета, указанные в разделе 2. Используй `ThemeData` во Flutter для глобальной настройки шрифтов Libre Baskerville и Instrument Sans.
4.  **Error Handling:** Оборачивай запросы к Firebase в блоки try/catch, добавляй индикаторы загрузки (CircularProgressIndicator) при ожидании данных.
